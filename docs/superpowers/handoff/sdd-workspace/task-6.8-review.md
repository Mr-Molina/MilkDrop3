- ✅ (b) Burn: mfs:3513 targets m_lpVS[1], which is the warp target (986). D3DX compares the whole 32-bit ARGB value, alpha included, so only opaque pixels whose RGB equals ck&0xFFFFFF are keyed, and they become 0x00000000. ck = 0 keys opaque black. `apply_colorkey` (image_load.rs) does exactly this, and both the unit test and the GPU test pin it. ### Strengths
- Every departure from the brief is grounded in the C++ and correct, including the commented-out y flip and the undo quirk for a burnt sprite that is not killed.
- The GPU tests check real behaviour: burn persistence with a burn = 0 control, order by mutation, wrap with repeat, colour key on readback, and log-once with a stale-id frame.

### Issues
#### Critical
- None.
#### Important
1. textures.rs `kill_sprite` together with texcache.rs `remove`: no reference count. KillTex releases the surface only for the last slot that references it (texmgr.cpp:156-165), but `load_sprite` hands every instance the same id (texmgr.cpp:76-87 instancing). Killing one instance therefore makes all instances stale, and `draw_sprites` silently skips them. Presets that launch the same image twice, such as a sprite with `done` that is re-launched while another copy is alive, lose the survivor. Fix: count instances per id (increment on an instancing hit in `load_sprite`, decrement in `kill_sprite`, remove at 0), and add a test that kills one of two instances and checks the other still draws.
#### Minor
1. No on-screen test of image orientation (whether the image is upright): every GPU sprite is a solid colour or uses a horizontal pattern. The vertical UV direction is pinned only by the unit `quad_corners_flip_and_uvs` combined with the 6.7a projection. Add a top/bottom two-colour image to the orientation test.
2. Blend modes 2-4 and colour modulation are checked as state and diffuse values only; there is no readback (mode 3's SrcColor and mode 4's texture-alpha path have no GPU coverage).
3. comp.rs `record_comp`: the `over: (&[TitleDraw], &[SpriteDraw])` tuple is accessed as `over.0`/`over.1`; named parameters or a small struct would read better.
4. Report citation mfs:1133-1135 should be 1134-1136.

### Assessment
**Task quality:** Needs fixes. **Reasoning:** The geometry, blend table, colour key, burn timing, orientation and order all match the C++ under the binding rulings. However, `kill_sprite` drops a texture that `load_sprite` shares between instances, which diverges from KillTex's reference count and makes live sprites vanish.
