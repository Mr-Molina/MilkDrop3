### Finding Verdicts
- **1. layout_all atlas retry never fired / stale UVs after growth or reset** — ADDRESSED. text_draw.rs layout_all now records `(font, generation)` after each item's own layout and compares each against the font's final generation, so an earlier item whose atlas a later item grew or reset triggers a second pass. A layout is self-consistent after its own call (layout re-reads tex_size after its own grow/reset), so the per-item generation is the right key. Unit test `text_draw::tests::layouts_are_redone_when_a_later_item_grows_the_atlas` genuinely pins the retry: items are pushed without draw-time layout, item 0 is laid out at 256 px, item 1 (about 190 distinct 40 px glyphs) grows the atlas, the test asserts generation > 0 and `laid[0] == fresh layout`; without the retry laid[0] keeps the old tw/th UVs, which differ from the fresh ones. The implementer's report of RED with the retry disabled is consistent with the code. One pass suffices for growth: the second pass finds every glyph placed (grow keeps all glyphs in place), so nothing changes generation. After a reset the second pass re-rasterizes every item's glyphs; it only fails to settle if the union of glyphs outruns the 2048 px atlas, in which case the loop ends unsettled (see Minor below).
- **2. draw_box must be DrawDarkTranslucentBox** — ADDRESSED. text_pass.rs:175 pushes `Item::DarkBox`; text_draw.rs flush_text routes it to `ctx.text_under` (all flushes), and record_text draws `under` first with `BlendMode::Alpha` (blend.rs:82 SrcAlpha/OneMinusSrcAlpha) then the in-order list. `DARK_TRANSLUCENT_BOX = [0,0,0,0xD0]` is defined at text_pass.rs and exported in lib.rs. `draw(.., dark_box)` still pushes the opaque `Item::Box` before its text (text_pass.rs:153) and `dark_box_precedes_text` is kept. Test `draw_box_stays_under_text_queued_before_it_and_blends` queues the box after the text, expects about [0,0,100,255] blended pixels and text-coloured glyph pixels on top, and checks the constant.
- **3. A second flush_text growing or resetting the atlas must not leave stale texels for the earlier flush** — ADDRESSED. sync_atlas keys the slot on `(texture, generation)` and creates a fresh texture on any generation change, even at the same size (the earlier size-only check missed a reset); earlier `TextDraw::Glyphs` hold a clone of the old texture. In-place `write_texture` happens only within a generation, adding glyphs at unused positions, so earlier draws are unaffected. Caveat: `earlier_flush_survives_atlas_growth_in_a_later_flush` does not isolate this. `draw` lays out at draw time, so the growth happens CPU-side between flushes and the old size-change check would also have passed; the reset path has no test (Minor).
- **4. Flush/present/resize constraint documented** — ADDRESSED. flush_text doc (text_draw.rs) and Renderer::resize doc (renderer.rs) both state it.
